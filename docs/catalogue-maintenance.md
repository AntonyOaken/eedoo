# Каталог «Попути»

## Обновление OSM

`python scripts/data/catalogue.py refresh`

Загружает отдельные полные наборы достопримечательностей и заведений для трёх городов. При сбое пробует меньшие участки. Каталог не заменяется, если хотя бы один набор неполон, содержит сообщение об ошибке, пуст, старее предыдущей версии или сократился более чем на 20%. Все ответы сначала проверяются; изменения публикуются обычным обновлением сайта. `--resume` разрешает явно использовать сохранённые ответы незавершённого запуска, с проверкой дат относительно текущего каталога. Это ручной процесс, расписание не подключено.

Дата `dataUpdatedAt` означает дату состояния OSM, а не подтверждение расписания владельцем. Устаревшие сведения в самом OSM останутся после новой выгрузки. Отсутствие объекта в другом источнике не доказывает закрытие. Не исключаем исторические руины только из-за отметки abandoned.

`python scripts/data/catalogue.py audit` показывает количество объектов, заполненность расписаний, ссылки на фотографии и кандидатов на дубли. Совпадение названия и расстояние до 25 м требуют проверки; автоматического удаления нет.

## Сравнение с Overture

Для инструмента требуется Python-пакет `duckdb` и расширение `httpfs` (`INSTALL httpfs` один раз). Инструмент предназначен для обслуживания данных, не используется при загрузке сайта.

`python scripts/data/compare-overture.py --release YYYY-MM-DD.N --output /absolute/path/report.json`

Читает небольшие центральные участки Петербурга, Кургана и Пхукета. Географические фильтры применяются к облачным файлам. Совпадение имён и координат — только кандидат на соответствие. Отчёт содержит выпуск, дату сравнения и исходные sources с лицензиями; не импортирует данные автоматически. Название на другом языке или отличия категорий могут дать ложное несовпадение. Для использования конкретной записи нужно проверить условия её источника: https://docs.overturemaps.org/attribution/ .

## Проверенные исправления

`lib/catalogue-corrections.json` хранится отдельно от выгрузок. Исправления применяются по стабильному ID объекта после сборки каталога ко всем городам, поиску, маркерам и маршрутам. Прежние проверенные сведения официальных сайтов перенесены сюда без изменения фактов и даты проверки.

```json
{
  "osm-node-123": {
    "patch": {"openingHours": "10:00–20:00", "hoursSource": "https://example.org/hours"},
    "checkedAt": "2026-10-05",
    "verifiedFields": ["openingHours"],
    "reason": "Расписание подтверждено на официальном сайте"
  }
}
```

Это пример структуры, не реальная запись. Для закрытого места используйте `hidden: true` и в reason укажите свидетельство и ссылку. `removeFields` удаляет неверные поля, когда замены нет. `verifiedFields` перечисляет только реально проверенные сведения. Исправления не теряются при следующем импорте; при изменении OSM ID их нужно перенести на новый ID после проверки. Исчезнувшая запись не воссоздаётся исправлением.

Фотографии хранят источник, автора, лицензию и ссылку на неё. Новый импорт не заменяет подготовленные фотографии объектов; произвольные image URL не означают разрешение на использование.
