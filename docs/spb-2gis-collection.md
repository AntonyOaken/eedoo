# Петербург: сбор 2ГИС

Дата последних наблюдений: 11 октября 2026 года. Режимы: «По пути» и «Не спешу».

## Приоритет данных

Все полученные факты 2ГИС заменяют прежние значения, включая заполненные названия,
координаты, адреса, контакты, расписания и фотографии. Отсутствующее поле не
считается утверждением об отсутствии сведений. Новые места добавляются независимо
от наличия в старом каталоге. Поиск обнаруживает объекты; подробная карточка
подтверждает контакты, недельное расписание, доступность и фото.

Сопоставление использует имя/псевдонимы и координаты. Близость сама по себе не
подтверждает тождество. Явные совпадения больших комплексов с отличающимися
координатами входов сохранены в `spb-2gis-matches.json`. Все решения и исключения
есть в `spb-2gis-audit.json`.

В галерее ожидать либо фото, либо видимую кнопку «Добавьте сюда фото и видео!».
Второе состояние подтверждает отсутствие предоставленных фото: сохранить

Обычный timeout без подтверждённого пустого состояния по-прежнему требует retry.

На обычном timeout навигации сборщик теперь сверяет фактический URL и
видимую страницу; продолжение допускается только для уже открывшейся нужной
страницы. Проверки идентичности и блокировок сохранены. Размер партии уменьшен
до трёх вкладок из-за технических timeout браузера (максимум остаётся шесть).
Обнаруженное рассогласование очереди устранено: ID `5348660212679593`
возвращён в очередь и повторно прочитан. Финальная сверка: 350 удалённых IDs
подтверждены наблюдениями, потерь и дублей нет.

Сборщик держит состояние между партиями. Не запускать несколько писателей и
не импортировать одновременно с браузерной записью. Полностью дождаться открытия
исходников до запуска. На обычных timeout проверить видимую страницу и возобновить
очередь. На подтверждённой проверке на робота остановиться по browser policy.

Дополнительные сведения открывать по наблюдённой ссылке info: переключение
SPA-вкладки часто не показывало содержимое. Сохранён один подтверждённый повтор
для Мариинского театра; остальные infoPending нужно пройти повторно новым
сборщиком. Явные типы и видимые рубрики карточки имеют приоритет над поисковой
темой: театр в поиске парков не становится парком. Музейная реклама продажи чая
исключается по наблюдённой рубрике.

Если публичная ссылка достопримечательности 2ГИС перенаправляет на один из её
явно сохранённых `relatedIds`, сборщик принимает связанную карточку, но сохраняет
исходный URL и ID очереди как основной источник. Любое иное несовпадение ID
по-прежнему останавливает пакет.

Браузер иногда возвращает путь фото, которое затем исчезает из временной папки.
Сборщик проверяет файл и копирует его в стабильную папку общего каталога
`/home/oai/share/spb-photo-checkpoints` сразу после загрузки. Импорт преобразует
фото в `public/photos/spb/2gis`. Недоступные фото явно сохранены в assetPending;
это не успешная загрузка. Импортировать промежуточный результат между партиями
не реже чем через 10 минут, ожидая его завершения, чтобы быстрее закреплять фото
в каталоге; после импорта и изменения наблюдений перезагрузить модуль с новой меткой импорта,
чтобы его состояние соответствовало сохранённым файлам очереди и наблюдений. Временные download
пути убирать только когда итоговый локальный JPG проверен. Неразрешённые пути
сохранять вместе с retry; не считать их переносимыми фото.

Для лимита архива Sites 256 MiB крупные фото оптимизированы до 1024 пикселей
по длинной стороне; новый импорт использует JPEG quality 82, progressive.
Фотографии и атрибуция сохранены. Повторно проверены итоговые JPG.

Общий `completed` допустим только после пустых очередей подробностей, фото,
инфо и ошибок, пройденных проверок и успешной публикации.

## Продолжение

1. В активном `cua_repl` прочитать документацию браузера, открыть наблюдённую
   ссылку из `detailPending`, вызвать `collect2GisParallelBatch(root, tabs)` (не более шести вкладок) из
   `scripts/collect-spb-2gis.browser.js` с настоящим браузерным tab.
2. Ожидать каждую небольшую партию. `root` — путь checkout в браузерном
   общем каталоге `/home/oai/share`. Сборщик сохраняет результат и очередь
   после каждой карточки. Не запускать необслуживаемую фоновую задачу и не использовать Node
   HTTP, секреты фронтенда или недокументированные API для обхода браузера.
3. Для выдачи нажимать видимые ссылки пагинации. Прямое открытие далёкой страницы
   иногда возвращает первую: перед сохранением сверять фактическую выдачу.
   Сохранять все новые наблюдённые ссылки; не ограничивать количество точек.
4. Сохранять контактные факты, структурированные признаки доступности и ссылки
   источника. Длинные редакционные тексты не копировать; описания пересказывать.
   Изображения скачивать через `downloadMedia`; импорт переносит их в `public`.
5. При явной проверке на робота остановиться и следовать политике браузера.

У успешно импортированных фото нет временных путей скачивания; повторный импорт

импортом. Состояние `completed` допустимо только при явно завершённом обнаружении,
пустых очередях `detailPending`, `assetPending`, `infoPending` и отсутствии нерешённых ошибок.
